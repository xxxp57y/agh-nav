入口：**http://127.0.0.1:43123/**

> 这个才是"会思考"的那一层：**用户说人话 → 大模型理解 → 调我们做好的导航工具 → 机器人真的动
> → 右侧可视化同步变化**。下面的 `navlive`（43121）是手；`43122` 那套 harness 是仪表盘；

## 2. 架构

```
浏览器 ──▶ 43123  agnes_agent.py        模型循环 + 工作区/历史 + 事件流
                     │  ├─ ModelClient   → api.agnes-ai.cn（chat/completions + tools）
                     │  └─ NavTools     → 43121 navlive（真导航）
                     └─ workspaces/<ws>/threads/<id>.json   逐条落盘
```

### 模型循环（一轮对话）

```
用户说一句
  → 组装 [系统提示 + 历史 + 本轮] + 9 个工具定义，发给模型
  → 模型返回 tool_calls
      → 我们真的执行（打到 navlive）
      → 把工具结果（JSON）作为 role=tool 回喂
  → 模型再想 …… 直到它不再调工具，输出人话
  → 落盘：用户消息、助手回复、**每次工具调用的参数与返回**（trace）
```

工具执行失败**也照样回喂给模型**（带 `ok:false` 与错误原文），这样它能改口说
"这个场景没有这个地方，可选的是…"，而不是崩溃或硬编。

### 工作区 / 历史

刻意用**文件**而不是数据库，理由是这种东西要能用眼睛看、能 diff、坏了能手修：

```
workspaces/
  default/
    workspace.json                 # 工作区元数据
    threads/th-xxxxxxxx.json       # 一条对话线：messages + trace + context
```

- `messages`：user / assistant 原文（重进对话时重放）
- `trace`：每次工具调用的 `{tool, args, ok, error, result, elapsed_s}`
- `context`：最近一次观察到的 scene_id / episode_id / 状态

写入用"临时文件 + 原子替换"，避免半个 JSON。目前只有一个 `default` 工作区，
但结构留好了（一个项目/一个场景一个工作区）。

### 九个工具（模型的"手"）

| 工具 | 作用 | 关键点 |
| --- | --- | --- |
| `nav_status` | 看服务是否可用 | 模型通常第一步就调它 |
| `nav_list_scenes` | 列场景与自然语言任务 | `with_tasks=true` 才带指令（很长） |
| `nav_open` | 载入场景/任务 | 换场景 8–20 秒 |
| `nav_list_places` | 列地名册 | **下指令前必须先看** |
| `nav_go_to_place` | **按地名派活** | 收名字不收坐标；见下面的自动重开 |
| `nav_observe` | 读真实状态 | 回答"到哪了/还剩多远" |
| `nav_pause` / `nav_resume` | 暂停/恢复 | |
| `nav_restart_episode` | 重开本轮 | 会重载环境，几十秒 |

**一条重要的工程决定**：`nav_go_to_place` 内部**发现回合已结束就先自动重开再派活**。
原因是 Habitat 的 VLN 回合判定成功后就结束，之后 `env.step()` 一律被拒；而 navlive 的
`goto` 会把 `episode_finished` 清成 False 并**接受**这次派活，机器人却一步都不走 ——
现象就是"模型说出发了，用户看到没动"（这是实测踩到的，不是推测）。
现在这个细节由工具兜住，用户和模型都不用管。

## 3. 界面（三栏，右侧把屏幕用起来）

```
┌────────────┬──────────────────────────┬─────────────────────────┐
│ 工作区     │  对话                    │  可视化（常驻右侧）     │
│ 历史对话   │  用户/助手气泡           │  第一人称画面           │
│ ＋新对话   │  工具调用明细            │  楼层图·轨迹·地标       │
│            │  快捷指令 chips          │  机器人状态             │
│            │  [输入框] [发送]         │  模型调了什么 / 事件流  │
└────────────┴──────────────────────────┴─────────────────────────┘
```

- **左**：工作区下拉、`＋新对话`、历史对话列表（点一条就重放它的消息与工具轨迹）
- **中**：对话；每条助手回复下面附"本步工具调用"；底部有快捷指令（它现在在哪 / 去沙发 / 停一下…）
- **右**：**常驻**可视化 —— 画面、地图（地标+轨迹+机器人+当前目标）、状态、`模型调了什么`、事件流。
  地图**点一下开大图**（右栏窄，细节看不清时用）。
- 顶栏：agent 状态、模型名与 token 用量、场景·任务、步数·回合

        需要换到另一个带游泳池的场景吗？或者客人去厨房/卧室/客厅？

  工具: nav_observe

## 5. 系统提示里写死的铁律

`agnes_agent.py` 的 `SYSTEM_PROMPT` 明确要求模型：

1. **绝不低于凭记忆编造地名或坐标** —— 必须来自 `nav_list_places`，没有就照实说并念候选
2. **别假装机器人动了** —— 问进展先 `nav_observe`
3. **注意"目标就在身边"** —— 工具返回带 `warning` 时要如实说明，别说"正在前往"
4. **回合结束要主动说明**，并在用户同意后重开
5. **坐标只用来解释，不用来下指令**
6. 没把握先看一眼，不要猜

## 7. 踩过的坑

| 现象 | 真因 | 修法 |
| --- | --- | --- |
| 模型说"出发了"，机器人**一步没动** | navlive 的 `goto` 会清掉 `episode_finished` 并对已结束的回合返回成功，但 Habitat 拒绝 `step()` | 工具内**先检测回合已结束 → 自动重开 → 再派活**，并在返回里带 `robot_after_1_5s` 供核对 |
| 右侧工具列表**出现重复行** | 流事件和 `/api/chat` 返回都渲染了一次，且流事件里没有完整 args | 工具行只由 `/api/chat` 返回渲染；流只用来更新"正在调用 X…" |
| 密钥**所有公开端点都 401** | 这个 key 是 Agnes 自有网关的，不是 DeepSeek/OpenAI 的 | 从仓库里 `packages/ai/src/adapters/pi/providers/agnes-ai.ts` 找到 `https://api.agnes-ai.cn/v1` |
| 起无头浏览器**隧道就断** | Edge 抢连接/被一起清掉 | 先起浏览器，再检查并重建隧道；测试脚本加"页面加载了吗"的前置断言 |

## 8. 会话隔离（"新对话串台"的修复）

用户报的问题：**开新对话后，在新对话框里问的问题会被响应在旧对话框里；切换会话很卡；
换场景后右侧可视化不变或显示错误。** 根因不在前端，在 navlive ——
`Session(self.env, ...)`，**所有会话共用同一个 `env`**，而且 `_open` 会把旧会话标记
`session_closed`，于是新对话直接顶掉旧会话。

### 8.1 现在的机制

* **每个 `Session` 自己记住** episode / 目标 / 轨迹 / 事件 / 标定（本来就有，只是以前被覆盖）
* **显式焦点**：任何针对某会话的请求先调 `LiveService.focus(session)`，
  它把环境切到该会话的 episode 并瞬移回该会话的位姿
* **Agent 侧**：`thread.context.session_id` 记住这条对话用哪个会话；
  每次 `_run` 把它装进 `NavTools.session`，跑完读回来存下
* **前端**：`viewSession` 表示"右侧可视化在看哪个会话"，
  切对话时置为该对话的 `context.session_id`，并每 0.9 秒与 `/api/thread` 对齐一次

### 8.2 性能：从 24 秒降到 0.01 秒

两处优化，缺一不可（都实测过）：

**① 环境按场景缓存（`NAVLIVE_ENV_CACHE`，默认 3）**
habitat 换场景要重建 stage/navmesh，实测 **16–25 秒**。以前只有一个环境，
所以在两个场景的对话之间来回看 = 每次都重载。现在每个场景持有自己的环境实例：

| 切换类型 | 优化前 | 优化后 |
| --- | --- | --- |
| 同 episode（同场景同任务） | 3.2 s | **0.00 s** |
| 不同 episode（同场景换任务） | 3.2 s | **0.00 s**（第二次起，环境已缓存） |
| 跨场景（环境已缓存） | 24 s | **0.01 s** |
| 跨场景（首次加载该场景） | 24 s | 16 s（一次性，之后走缓存） |

**② 只有 episode 真的变了才 `env.reset()`**
原来无条件 reset，导致"同任务的两个会话来回切"每次都要 8–17 秒。
现在只在 episode 变化时 reset。

**③ `/view` 非阻塞**
`/view` 在目标会话不是焦点时，**先把该会话缓存好的快照返回**，切换交给后台线程；
另外只返回状态与图片版本号，不重算画面/地图。所以切会话时界面立刻变，
机器人状态随后自动刷新，不会卡住 20 秒。
`/frame.jpg` 与 `/map.png` **只读该会话缓存的字节**，绝不触发焦点切换。

```

  A(2) 0.00s ...                    B(2) 0.01s ...

  B 会话 nl-…738917 场景 TbHJrupSAjP

  两条对话的右侧场景不同（TbHJrupSAjP vs zsNo4HB9uLZ）
  来回点 2 轮，每次都：高亮对、可视化对象对、场景对
```

### 8.4 一件必须说明的事

**"两条对话同时在跑"做不到。** 因为只有一个 `habitat.Env` 在推进（即使有多个环境实例，
同一时刻也只有焦点那一个在 tick）。所以：

* **后台对话是"暂停"而不是"继续跑"** —— 它的 episode、目标、轨迹、事件都在，
  切回去就从原处继续；
* 界面上会显示「正在切换会话…」，切换完成后自动续上；
* 这是仿真器的限制，不是前端 bug。要真并发得给每条对话开独立进程 + 独立 GPU 上下文。

## 10. 已知限制（在原有限制之外补充）

7. **跨场景首次加载仍需 16–25 秒**（要建新环境并载入 .glb）。`NAVLIVE_ENV_CACHE`
   是内存换速度：每个环境约占 1–3 GB 显存，`nvidia-smi` 显示 49 GB 可用，所以默认 3 是安全的；
   如果把上限调得比场景数还大，那些环境会一直占着显存。
8. **后台对话不推进**（见 8.4）。
9. **`/view` 的 `activating` 标志**说明焦点还在后台切换中，界面据此显示
   「正在切换会话…」；此时读到的是该会话上一次的快照。


1. **只有一个工作区**（`default`）。多工作区/多用户还没做。
2. **token 用量千级起步**（一次派活约 8k prompt）：每轮都把 9 个工具定义 + 系统提示发过去，
   没有做工具裁剪或提示压缩。要省钱可以做"按场景预筛工具"。
3. **一次只跑一轮对话**（Agent 里加了锁）：两条指令同时来会排队，不会抢机器人。
4. **`nav_go_to_place` 里那 1.5 秒的复核是同步等待**：让工具慢一点点，换来"模型不会报假进展"。
5. **轨迹/地标要等标定**：机器人没走动过（<0.5 m）时地标画不准，右侧会显示"未标定"。
6. 模型偶发会先调 `nav_status` 再调 `nav_list_places` 才派活（多一次往返），
   属于保守行为，可以接受。
