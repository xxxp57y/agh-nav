# 实时导航工作台（自带控制面板版）

> 参考实例（院递工作台）有「实时仿真画面 / 机器人状态 / 楼层图与轨迹 / 遥测」，
> 但那是**只读**的展示。这一版要的是**能派活、能干预**的工作台 ——
> 人在页面上说话 → 机器人真的走。

入口：**http://127.0.0.1:43122/**（需要一条到服务器的 ssh 隧道，见文末）

---

## 1. 页面分六块，对应参考实例的六个功能

| # | 区域 | 做什么 |
| --- | --- | --- |
| ① | 任务安排 | 选 Matterport3D 场景 → 列出该场景的自然语言任务（13–15 条）→ 载入 |
| ② | 派送指令 | 用人话说去哪（"带客人去客厅"），解析成真实坐标并让机器人走 |
| ③ | 地名册 | 场景里"叫得出名字的地方"，点一下直接派过去 |
| ④ | 演示控制 | 暂停 / 恢复 / **重开本轮** |
| ⑤ | 机器人状态 | 任务指令、当前目标、位置、剩余距离、已走步数、碰撞、plan_age、回合判定、计划队列 |
| ⑥ | 画面·地图·事件 | 第一人称真渲染 + 整层楼平面图与轨迹 + 决策事件流 + 「最近一次操作」核对区 |

所有按钮都打真实 HTTP 请求（`/open`、`/action`），**不是演示动画**。

## 2. 控制闭环（实测）

```
派「厨房」        → 机器人走 61 步，位置 (15.07,-4.49) → (6.40,-2.44)
点「重开本轮」    → episode_over → episode_restarted，步数归 0，回到起点
再派「卧室」      → episode_over 之后本来 step 会被拒；重开后真的又走了 62 步
```

**为什么必须有「重开本轮」**：Habitat 的 VLN 回合在判定成功（距目标 < 3 m）后就结束，
之后 `env.step()` 一律返回 *"Episode over, call reset before calling step"*，
于是再派一个更远的地标**不会执行** —— 在页面上看就是"派了活但机器人不动"。
`Session.restart()` 用 `env.reset()` 把 agent 放回本回合起点，清空计划与步数，
所以演示时能"一单接一单"地做下去。

## 3. 真点击验收（不是只看 DOM）

光看 DOM 只能证明"渲染出来了"。这次踩到的坑恰好是：
**页面元素全在、但注入把 JS 写坏了，所有按钮都是死的**。
所以验收脚本必须真的点一下。

`_tools/click-test.mjs`：Edge `--remote-debugging-port` + CDP（用仓库里已有的 `ws`），
读页面状态 → `btnRestart.click()` → 再读一次：

| | 点击前 | 点击后 |
| --- | --- | --- |
| 步数 | 第 125 步 | **第 0 步** |
| 状态 | 已结束（需重开本轮） | **进行中** |
| 事件数 | 6 | 7 |
| 重开按钮 | 可点 | 自动置灰 |

服务端 `/state` 的事件流里也能看到 `episode_restarted` —— 点击确实落到了仿真。

用法：

```bash
# 先手工起一个带调试端口的 Edge（某些环境策略会忽略 --remote-debugging-port）
msedge --headless=new --remote-debugging-port=9444 --user-data-dir=%TEMP%\e http://127.0.0.1:43122/
node /srv/agh-demo\_tools\click-test.mjs http://127.0.0.1:43122/ <edge路径> 9444 result.txt --attach
```

## 4. 这一轮踩到的三个坑（都会表现为"页面打不开/没反应"）

| 现象 | 真因 | 修法 |
| --- | --- | --- |
| 页面有元素但**全是死的** | 注入服务地址时把 `window.__NAVLIVE__` 这个标识符也替换掉了 → 生成的 JS 语法错误，整段脚本不执行 | 占位符换成不冲突的 `__NAVLIVE_BASE__`，只替换那一处字符串 |
| 服务重启了但**跑的还是旧代码** | `tmux kill-session` 之后端口上还活着一个**更早的**进程（`ss -ltnp` 能看到），新的绑不上就静默退出 | 先按 `ss -ltnp` 找 pid **杀干净**再起；起完确认日志里是新的启动行 |
| 浏览器**什么都打不开** | 到服务器的 ssh 隧道断了（43121/43122 是转发端口，不是服务本身） | 双击 [打开实时导航.cmd](/srv/agh-demo\_tools\打开实时导航.cmd) 重建隧道 |

## 5. 需要的一条隧道

服务器上服务一直跑着，但浏览器要用它们必须有隧道：

```
43122  实时导航工作台（本页）
43121  navlive 服务（/state /landmarks /frame.jpg /map.png …）
43120  AGH 实例（导航工作台插件面板；DSH Desktop 自身也占用本机 43120，故不在此转发）
```

一键脚本：[打开实时导航.cmd](/srv/agh-demo\_tools\打开实时导航.cmd)
（清旧隧道 → 建新隧道 → 探活 → 开页面）

## 6. 已知限制

1. **地名册是"指令里提到过的地点"，不是完整房间清单**（这台 habitat 读不到语义区域标注）。
   某个场景没被指令提到的房间就是没有；此时接口明确报"没有这个地标"并给候选，不会瞎走。
2. **走到成功点后回合会结束**，必须点「重开本轮」才能继续派活（见第 2 节）。
3. **服务端地图上的地标文字画不出来**（这台机器 Pillow 9.5 缺 `getmask2`），
   所以地标名字由**前端**在 SVG 上画，服务端只画方块。
4. **换场景要 8–20 秒**（重载 `.glb`），同场景换任务约 3 秒；页面会提示。
5. **页面右上角的「回合判定：成功」是 Habitat 的官方判据（距目标 < 3 m）**，
   和我们自己设的地标目标可能不同 —— 派了更远的地标时，官方判据仍可能先报成功。
