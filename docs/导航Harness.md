# 导航 Harness（实时导航工作台 · 控制台版）

入口：**http://127.0.0.1:43122/**

> 参考实例（院递工作台）是**只读展示**；这一版是**能派活、能干预**的导航 harness，
> 而且按"外壳 + 左侧功能栏"的形态组织，而不是把所有东西堆在一页。

---

## 1. 界面结构

```
┌───────────────────────────────────────────────────────────────┐
│ Agnes · 导航 Harness   [navlive 在线] [场景] [任务#] [步数·回合] │
├──────────┬────────────────────────────────────────────────────┤
│ 工作     │                                                    │
│  对话    │   主区：按左侧选中切换                              │
│  控制台  │                                                    │
│ 查看     │                                                    │
│  可视化  │   ← 画面/地图/轨迹单独一个入口                      │
│  地名册  │                                                    │
│ 系统     │                                                    │
│  批量分析│   ← 离线分析从实时里拆出来，单列                   │
│  诊断    │                                                    │
└──────────┴────────────────────────────────────────────────────┘
```

| 入口 | 作用 |
| --- | --- |
| **对话** | 用大白话下指令；每条都记下"用户说了什么 / 调了哪个工具 / 参数 / 返回（含世界坐标与地图像素）"，是"自然语言 → 工具 → 可见结果"这条链的展厅 |
| **控制台** | 任务安排（选场景/选任务/载入）、演示控制（暂停/恢复/重开本轮）、机器人状态、实时画面、事件流 |
| **可视化** | **单独一屏**：第一人称画面 + 楼层图轨迹 + 地标 + 关键数值 |
| **地名册** | 名字 → 世界坐标 → 地图像素，一张表摊开；点一行就派过去 |
| **批量分析** | 离线那套（八场景 × 五套恢复配置的失败归因），从实时里拆出来 |
| **诊断** | 接口连通性、地图标定参数、最近一次操作的原始返回 |

URL 支持 `#viz` / `#console` 等直接跳到某个视图。

## 2. 地图坐标（这一轮的核心修正）

**之前地标和轨迹全是错位的，落在地图黑色区域。根因：**

habitat 的 `to_grid` 对两个轴用的分辨率不同 ——

```python
grid_size = (abs(upper[2]-lower[2]) / grid_resolution[0],   # z 方向
             abs(upper[0]-lower[0]) / grid_resolution[1])   # x 方向
grid_x = (x - lower[2]) / grid_size[0]
grid_y = (z - lower[0]) / grid_size[1]
```

再加上 `map_padding` 与「地图按最长边缩放到 map_resolution」，
**x 与 z 的像素密度本来就不一样**（本机实测 **77 vs 80 px/m**）。
用单一 `meters_per_pixel=0.01` 换算，误差会随距离累积，远端地标直接飞到图外。

**做法**：不再自己推，改为**解**。

1. 服务端每 tick 用「当前世界位姿 ↔ 当前 `agent_map_coord`」喂一条样本 ——
   这是 habitat 自己算的坐标，天然精确对应，不需要瞬移、不需要猜边界；
2. 攒到两条**相距 >0.5 m** 的样本就解出 `col = scale_x·x + origin_col`、`row = scale_z·z + origin_row`；
3. 服务端把地标/轨迹/终点/机器人的**像素坐标**放进 `/state` 的 `overlay`，
   前端只把 SVG 叠在 PNG 上（PNG 与 SVG 共用同一坐标系，所以必定对齐）。

**验证**（按像素类型判在不在楼面上）：

```
地标 沙发/客厅/桌子 (1242.8, 792.6) → 地板
地标 厨房 (697.2, 450.4) → 地板      地标 卧室/床 (764.8, 305.1) → 地板
终点 (1242.8, 792.6) → 地板          轨迹 62/62 点 → 地板
```

另外「重开本轮」用 `env.reset()`，会把 agent 放回本回合起点；标定样本随之清空重攒。

## 4. 踩过的坑（都会表现成"页面打不开 / 点了没反应"）

| 现象 | 真因 | 修法 |
| --- | --- | --- |
| 元素都在但**全是死的** | 注入服务地址时把 `window.__NAVLIVE__` 标识符也替换了 → JS 语法错误，整段不执行 | 占位符改成不冲突的 `__NAVLIVE_BASE__` |
| 重启服务后**跑的还是旧代码** | `tmux kill-session` 后端口上还活着更早的进程，新的绑不上静默退出 | 先按 `ss -ltnp` 找 pid 杀干净再起；确认日志是新启动行 |
| 浏览器**什么都打不开** | 到服务器的 ssh 隧道断了 | 双击 [打开实时导航.cmd](/srv/agh-demo\_tools\打开实时导航.cmd) |
| 起无头浏览器后**隧道又断了** | 新起的 Edge 抢了 ssh 的连接/被一起清掉 | 先起浏览器、再检查并重建隧道（测试脚本里已加"页面加载了吗"的前置断言） |
| 点「重开本轮」**看似没反应** | `env.reset()` 要重载场景，耗时可达数十秒；只等几秒会误判 | 等状态里步数回到 0 再判定（测试脚本已改成轮询） |

## 5. 已知限制

1. **同一场景里多个地标可能共用一个坐标**：例如 `zsNo4HB9uLZ` 的「沙发/客厅/桌子」都在
   (13.05, 1.87) —— 因为不同回合的终点本来就是同一处，而指令用了不同说法。这是如实呈现。
2. **走到成功点后回合结束**，必须点「重开本轮」才能继续派活（见第 2 节）。
3. **若当前目标就在 3 m 内**，Habitat 会立刻判 success 并结束回合 ——
   表现为"机器人原地不动"。选远一点的地标，或先重开本轮。
4. **地名册是指令里提到过的地点，不是完整房间清单**（这台 habitat 读不到语义区域标注）。
5. **服务端地图上的地标文字画不出来**（本机 Pillow 9.5 缺 `getmask2`），
   所以名字由前端在 SVG 上画，服务端只画方块。
6. **批量分析那个页签目前只是入口**，离线分析能力在 `nav-agent-plugin` 的 `nav_*` 工具里，
   还没接进这个外壳。
