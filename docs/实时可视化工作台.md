# 实时导航工作台 —— 「选一个已跑好的场景，让机器人真的走过去」

> 这份文档讲的是 **navlive**：把 `agh-nav` 从"离线批量日志分析"扩成"在真实 Habitat 场景里跑单回合任务"的那一层。
> 入口是 AGH Web 工作台左栏的 **导航工作台 → 实时导航** 页签。

---

## 0. 一句话

以前这个仓库回答的是"**那一轮**跑得怎么样"（读 `closed_loop_steps_rank0.jsonl`，算指标、找失败、复算恢复通道）；
现在多了一条线回答"**现在这个场景里**，机器人去哪、到哪了"——它会真的在 Habitat 里一步步走，
工作台实时出**第一人称画面 + 2D 楼层图与轨迹 + 位姿/遥测 + 事件流**。

两条线的分工（别混）：

| | 离线 `nav_*` | 在线 `navlive_*` |
| --- | --- | --- |
| 回答 | 这一轮跑得怎么样、失败在哪、恢复通道会怎么动 | 现在这个场景里，机器人去哪、到哪了 |
| 数据源 | 服务器上的 run 日志（`bin/agh_nav_probe.py`） | 常驻的 navlive 服务（HTTP + SSE） |
| 会不会动 | 不会 | **会**（所以会动的工具都要审批） |
| 时间尺度 | 一次评估 ≈ 60–70 分钟 | 一步 5–8 ms，一个回合几十秒 |

---

## 1. 现场实测的关键数字（决定架构的就是这几个）

在导航服务器的 RTX 4090 上实测：

| 事情 | 实测 | 后果 |
| --- | --- | --- |
| `habitat.Env` 首次构建 | **约 23 s** | 服务要常驻，不能一次请求建一次 |
| 换场景（重载 `.glb`） | **8–20 s** | 打开会话时只换 episode，不换场景 |
| 换 episode（同场景） | **约 3 s** | 可以随便挑回合 |
| 单步 `env.step`（480×640 RGB + 1024 语义图） | **5–8 ms** | 8 Hz 的实时循环只用了约 5% 的时间预算 |
| navmesh 寻路走完一个回合 | 42–78 步，**0.3–0.4 s** 纯计算 | 走对路这件事本身不是瓶颈 |

结论：**瓶颈在"渲染 + 跨线程通信"，不在导航**。所以架构是
"一个常驻进程 + 一个只跑仿真的线程 + 只读快照给 HTTP"。

## 2. 架构

```
浏览器（Windows）
  │  ① AGH Web 工作台（同源 BFF）
  │     左栏面板 = nav-board-plugin 的 'ui:sidebar'
  │       · 实时导航页签  ──直连 HTTP──┐
  │       · 对照分析页签  ──服务桥─────┼─→ nav.board → 服务器 bin/agh_nav_probe.py
  │                                   │
  │  ② navlive 服务（默认 http://127.0.0.1:43121，需要端口转发）
  ▼                                   │
导航服务器                              │
  tmux: navlive                        │
    navlive/navlive_server.py  ◄───────┘
      ├── sim 线程（唯一碰 habitat/CUDA 的地方）
      │     · env.step(action)          ← ShortestPathFollower 给动作
      │     · 算指标（success/spl/距离/碰撞/plan_age）
      │     · 渲画面（JPEG，5 fps）与楼层图（PNG，2.5 fps）
      │     · 生成 JSON 快照（只有它写，HTTP 只读）
      └── 命令队列（HTTP → sim）：open / goto / pause / resume / note
  tmux: agh_nav_web
    agnes serve --port 43120
      └── @agh-nav/nav-agent-plugin：11 个离线工具 + 7 个实时工具
```

**为什么只有 sim 线程能碰 habitat**：第一版让 HTTP 处理函数直接调 `env.get_metrics()`，
Habitat 的渲染上下文跨线程炸掉（`GL::Context::current(): no current context`），整个服务退出。
现在所有 `env` 访问都在 sim 线程里，HTTP 只读一个原子替换的 JSON 字符串。

**为什么面板直连 HTTP 而不是走 AGH 服务桥**：实时那条是每 400 ms 变一次的高频数据，
走服务桥会把会话事件流淹没；对照表是低频且需要授权的，才适合走服务桥。



### 4.1 工作台左栏面板（可选）

`nav-board-plugin` 的「实时导航」页签代码已就绪，但要装进实例需要走 AGH 的包流程——
**这台实例的包流程坏在一个运行前就存在的 runtime snapshot 不一致上**，
定位与修复过程见 [AGH插件更新排查记录.md](AGH插件更新排查记录.md)。
在那条路走通之前，用 §4.2 的 MCP 路径拿到同样的工具能力。

### 4.2 通过 MCP 把实时工具接进 AGH（**已实测可用**）

AGH 原生支持 MCP，这条路不碰包状态机，改完工具只要重启子进程：

```bash
cd /srv/agh-demo/agh-src
export AGH_HOME=/srv/agh-demo/agh-home AGNES_PROFILE=local-dev
A="node packages/cli/dist/local/agnes.mjs"

# 1) 注册（stdio 走 node 跑同一个 mcp-server.mjs）
$A mcp add navlive --name 实时导航 --stdio node \
    --arg /srv/agh-demo/agh-src/agh-nav/mcp-server.mjs
# 2) 取 revision
$A mcp get navlive
# 3) 信任 + 启用（都要带 --expected-revision）
$A mcp trust  navlive --expected-revision <REV>
$A mcp enable navlive --expected-revision <REV>
# 4) 验证
$A mcp status navlive    # → connection=ready tools=7
$A mcp tools  navlive    # → 7 个 navlive_* 工具
$A mcp test   navlive --expected-revision <REV>
```

**两个必须的启动开关**（否则会报 `stdio executable is not allowed by profile policy`
或 `MCP_CONNECT_FAILED`）。工作台启动命令要带上：

```bash
AGNES_MCP_STDIO_ALLOWLIST='node,/usr/bin/node' AGNES_MCP_ALLOW_LOOPBACK_HTTP=1 \
  node packages/cli/dist/local/agnes.mjs serve --port 43120
```

- `AGNES_MCP_STDIO_ALLOWLIST` 是**精确匹配**的可执行文件清单：
  MCP 定义里写的是 `node`，就必须允许 `node`；只允许 `/usr/bin/node` 会连不上。
- 实测结果：`mcp status navlive` → `connection=ready … tools=7`，`mcp test` → `succeeded`。

## 5. 怎么用（这就是"自然语言驱动的导航"）

在聊天里直接说人话，Agent 会自己选工具、自己换算坐标：

| 你说 | Agent 会做什么 |
| --- | --- |
| 「看看有哪些场景可以跑」 | `navlive_scenes` → 把 4 个场景和它们的指令摆出来 |
| 「在 `2azQ1b91cZZ` 里做个任务」 | `navlive_open` → 打开会话，右侧立刻出画面与楼层图 |
| 「带客人从门口走到客厅」 | `navlive_goto` → 机器人真的开始走，轨迹实时长出来 |
| 「A 站暂时不能接收，先去 C 站」 | 再调一次 `navlive_goto` 换目标 → 画面与轨迹立刻改向 |
| 「它现在到哪了？」 | `navlive_state` → 位姿、剩余距离、碰撞、plan_age、最近事件 |
| 「先停一下，我要看一眼」 | `navlive_pause` / `navlive_resume` |

**改目标是这个工作台的核心动作**：`navlive_goto` 接受一串航点（世界坐标），
第一个是当前目标、其余排队；机器人立刻按新目标重算路径。
"中途改主意"在实现上就是再调一次它——不需要重启回合、不需要重跑模型。

## 6. 接口一览（工作台与插件只用这几个）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 服务是否在线、载入多少场景、当前会话、仿真频率、最近错误 |
| GET | `/scenes` | 4 个场景 × 13 回合（含每回合的自然语言指令、起点、终点坐标） |
| POST | `/open` | `{scene, episode?, instruction?}` 载入场景+回合，创建会话 |
| GET | `/state?session=` | 当前快照：位姿、目标、指标、轨迹、事件尾、楼层图仿射 |
| GET | `/events?session=&since=` | SSE 事件流（改派 / 到达 / 暂停 / 规划失败 / 卡住） |
| GET | `/frame.jpg?session=` | 最近一帧第一人称画面（JPEG） |
| GET | `/map.png?session=` | 最近一张楼层图（PNG，**不含轨迹**） |
| POST | `/action` | `{session, kind: goto\|pause\|resume\|note, …}` |

**轨迹由前端画**：`/map.png` 只给底图，`/state` 里给一个"world → 地图像素"的仿射
（锚点 + 0.01 m/px），前端用 SVG 折线盖上去。这样缩放、hover、重画都不用重传整张图。

## 7. 两个渲染坑（都踩过，别再踩）

1. **`top_down_map["map"]` 不是灰度图**，是 habitat 的语义索引图：像素值是常量
   （0 无效 / 1 可行走 / 2 墙 / 4 起点 / 6 目标 / 7 最短路径 / 9 目标框）。
   直接 `Image.fromarray` 存出来像素值只有 0–17，**几乎全黑**。
   必须先过 `habitat.utils.visualizations.maps.colorize_topdown_map()`。
2. **`fog_of_war.draw=True` 会把未探索区域压暗到 0.5 倍**，要"整层楼底图"就得关掉
   （`FogOfWarConfig(draw=False, visibility_dist=100, fov=180)`）。

顺带一个 habitat 专属的坑：`oracle_success` 这个测量项**不是内置注册的**，
它是 `internnav.habitat_extensions.vln.habitat_vln_evaluator` 这个模块**导入时**才注册的。
所以裸 `habitat.Env(config)` 会报 `invalid oracle_success type OracleSuccess`
——必须先 import 那个模块（与 `eval.py` 走同一条注册路径）。

## 8. 已验证 / 未验证（写作品文档时要一起写）

**已验证（服务器实测）**

- 4 个场景（`2azQ1b91cZZ` / `QUCTc6BB5sX` / `TbHJrupSAjP` / `zsNo4HB9uLZ`）× 13 回合全部可载入；
- navmesh 寻路在这 4 个场景各跑通一次：**4/4 success = 1.0**，到达后距终点 0.31–0.45 m，5–8 ms/步；
- 实时循环 8 Hz 连续运行 80 s 以上无错误（`last_error = null`）；
- 中途改目标真的改向（`plan_changed` 事件 + 轨迹改向）；
- 7 个 `navlive_*` 工具：契约通过、写工具逐条 `requiresApproval: 'always'`、只读工具真调返回实时数据（53/53）。

**未验证 / 限制**

1. **planner 目前是 navmesh 寻路，不是 VLA**。`ShortestPathFollower` 回答的是"怎么走过去"，
   不是"这句话该去哪"。把 InternVLA-N1 接成第二个 planner 是下一步（接口已经留好：
   `Session.tick()` 里换 `get_next_action` 的来源即可）。
2. **"这句话该去哪"现在靠 Agent 换算坐标**。场景里没有语义标注（"客厅""沙发"不是可查询的对象），
   所以 Agent 需要先确认坐标或从回合的起点/终点里挑。要真正"听懂家庭指令"，
   得再补一层语义地标（下一步）。
3. **每格 13 回合、SE≈14pt**：跨场景结论只能讲方向 + 逐回合配对，不能拿一次演示当对照实验。
4. **没有加速度/动力学**：动作是离散的（前进 0.25 m / 转 15°），适合"陪送导航"叙事，
   但不是真实的轮式/足式控制。
5. **端口转发是手工的**：面板直连 43121，没做转发时它会明确显示"服务未连接"并给出排查顺序
   （这是有意的降级，不是静默失败）。
