# 报告材料｜路线① 导航侧（赛题三问 × 证据）

> 全部数字来自服务器实测，口径一律标注。生成 2026-10-11。
> 数据源：`InternNav/logs/habitat/route1_*`、`long/logs/route1/pool8_*.json`、`FINAL_TABLE.txt`。

## 0. 一句话

**我们把"导航失败之后该做什么"从一句口号变成了一条可调用的链路**：
Agent 用自然语言就能（1）发起/查看 Habitat 导航评估，（2）拿到逐决策的环境反馈，
（3）用**与在线闭环同一份**判据算出"在哪些点应该要求重规划、能覆盖多少失败回合"，
并在 8 个场景 × 104 回合的对照表上选配置。

## 1. 对照赛题要求

### 1.1 自然语言驱动的导航任务执行

| 证据 | 数字/事实 | 复现 |
| --- | --- | --- |
| 现成评估资产 | 服务器上 **15 个 run**、每 run 50–52 回合、8 个场景 | `nav_list_runs` |
| 语言→评估 | `nav_run_eval` 用自然语言参数（budget_mode / watchdog / channels / episodes）在 tmux 里起一次闭环评估 | `agh_nav_probe.py launch` |
| 任务指令本身 | 日志里逐回合保留 Habitat VLN 指令（`episode_instruction`），工具会带出来 | `nav_observe_episode` |
| 进度可观测 | 完成回合数、逐场景计数、当前 Success、日志尾部 | `nav_run_progress` |

### 1.2 环境反馈分析

| 证据 | 数字/事实 |
| --- | --- |
| 逐决策反馈 | 每个决策点有：距目标、碰撞计数、plan_age、轨迹漂移、几何加权分、是否重规划、原因、是否有可执行动作 |
| 统一失败契约 | `FailureEvent`：类型 N1/N2/N4/N5 + `signals` + REFLECT 式归因（一句话 + 证据）+ 恢复动作 + 结果 |
| 官方失败标签覆盖率 | **11.2%–15.0%**（其余是 `model_invoked=False` 的 padded local STOP，落盘被改名为 `local_horizon_replan`） |
| 触发质量 | 几何加权分对"下一步真失败"的 AUROC：12 个 run 里 9 个 < 0.5，**均值 ≈ 0.44** |
| 权重真相 | 50% 权重压在两个**从未可用**的信号上（`uncertainty` 被关、`collision_risk` 从未提供）；活跃部分由 `plan_age`（纯计时器）主导 |

**这两条是路线① 最有价值的"负结果"**：不是"我们的模块没调好"，而是
**现有几何判据在信息论上就不指向失败**。引用时必须带上口径。

### 1.3 导航失败后的自主任务调整

| 证据 | 数字/事实 |
| --- | --- |
| 恢复动作空间 | `none / replan / local_escape / switch_instance / reparse_instruction / ask_clarification / escalate`，按失败类型给菜单 |
| 在线判据 | 两条**场景无关**通道：碰撞密度（8 动作内 ≥5 次）、进度停滞（12 动作内改善 <0.3 m 或远离 >0.6 m），各带冷却递增与每回合封顶 |
| 复用证明 | 插件调用的就是 `route1.nav.channels.TriggerChannels` —— **与在线 `overlay_v4` 同一份代码** |
| 通道有效性（推荐配置 r1grd4） | 触发 89 次 / 52 回合（1.71 次/回合），覆盖 **12/13 失败回合**，回合级精度 0.4444 vs 基率 0.2500 |
| 配置选型 | 见 §2 的 5×8 对照表 |

## 3. 三个被证伪的直觉（比正结果更值得写）

1. **"扩大恢复动作空间就能省 System-2"** —— 离线重放 13 个 run：省的调用比例 **0–1.6%**。
   动作空间是**接口**，不是能力：没有第 5 个信号，它就是一个永远走 replan 分支的 switch。
2. **"语义 Monitor 能提升失败预测"** —— n=82 的 A/B：几何 AUROC 0.457/0.417/0.389 vs
   语义 0.509/0.429/0.317（h=1/3/5），**都不优于随机**；Monitor 一次 LOST 都没报，
   因为这批 episode 的导航基本在轨（成功率 70%）——"指令-执行一致性"在走对的时候没有东西可检测。
3. **"单场景调出来的闭环能泛化"** —— R2A 在它的调参场景上 13/13 逐回合一致，
   到 `QUCTc6BB5sX` 上 5 个回合被碰撞看门狗（8 动作内 ≥6 次碰撞）直接 STOP 掉，
   只走 41–88 步就丢掉整个回合（真正的 episode 预算是 **501 步**）。

## 4. 工程实现要点（可核对）

| 点 | 说明 |
| --- | --- |
| 不改上游 | `InternNav/` 只读；两条通道用 out-of-tree monkeypatch（`route1/nav/overlay_v4.py`），只在"上游说别重规划"时加一次动作 |
| 零侵入可证 | 通道不触发时 `V4Scheduler.step()` 与上游调度器返回**逐位相同**的 dict；`selftest_overlay` 13/13 |
| 契约先行 | `FailureEvent` 的字段与 `route1-bridge-plan.md` §6 一一对应；插件产出的就是这套 dataclass 的 `to_dict()` |
| 自造 bug 披露 | `V4_CHANNELS=none` 曾只 gate 传感器推送、`evaluate()` 仍被无条件调用 → 污染了一臂；已修 + 加回归测试（`selftest_overlay` 第 6 条） |
| 回退设计 | 实时数据面不可用时工具返回**缓存快照**并显式标注 `source: cache` + `degraded.reason`；无缓存则**显式失败**（不是空结果） |

**真实会话 e2e 覆盖（这一条最关键：不是 mock）**：

（核对 `actual=running`、`trusted=true`）→ **11 个导航工具对模型可见** →
模型在会话里真的调用 `nav_compare_configs` / `nav_recovery_options` / `nav_failure_events`，
断言模型收到的是**服务器上的真实数据** → 看板包进入客户端名册（`ui:sidebar`），
`nav.board` 服务经 daemon→worker→Host 返回真实 5×8 数据（`guarded=0.7115`）。

AGH 原生集成自检具体验了什么（可核对的四层）：

1. **清单**：`parseAgnesPluginEntries` 解析两个包的 `agnes.plugins`，`inject` 与导出元数据一致；
2. **工具契约**：`checkToolDef` —— **11/11** 工具通过 AGH 的工具契约（含 meta 语义）；
3. **参数校验**：`validateAgainst` —— 缺必填 / 类型错 / 多余字段都被拒（`additionalProperties:false`）；
4. **前端与清理**：真实 Cordis fiber 挂载看板客户端模块 → **SSR 渲染出 5×8 对照表** → `dispose()` 后槽位清空。

期间用 AGH 自己的校验器抓到两个真实缺陷并已修复回归：
`meta.replay` 只能是 `safe|never|idempotent`（原来写了 `unsafe`）；
`meta.costHint` 必须是 `{credits?, wallMs?}` 结构（原来写了给模型看的字符串）。

**尚未完成的最后一公里**：把包装真的 `install/enable` 进一个运行中的 AGH 实例 —— **已完成**：
服务器实例（`AGH_HOME=/srv/agh-demo/agh-home`）上两个包都是
`desired=enabled actual=running trusted=true`，且 `tests/agh-session.e2e.mjs` 12/12 在真实会话里调通了导航工具。
无 GUI 的安装配方（pty 确认 + `capabilityHash` + trust + enable）写在 `README.md` §3.2.1。
唯一与"本地 AGH"的偏差：Windows 上 `build:local` 需要 MSVC 工具链（本机没有），
所以实例建在服务器（Ubuntu 22.04 / Node 24.14）上；本地工作区保留同一份可安装源码。

## 6. 引用时必须一起写的限制

1. 每格 **13 回合，SE ≈ 14pt**：单场景差异要 >28pt 才明显；只能讲方向和逐回合配对。
2. `budget_exhausted_no_goal` 是**两种情形合一**（预算用尽 / 主动 STOP 在错位置），
   日志不记录 Habitat `done` 的原因；用"同一回合在多个 run 里 steps 是否逐位相同"来分辨。
3. `recovery_only` 的**碰撞代价高**（15.47 次/回合）；R2A 的 0.88 是"看门狗把回合停掉"换来的，不可直接比。
4. 8 场景表是"主清单 run + 新场景 run"**拼接**出来的，依赖"episode 之间独立"这一假设（尚未做 8 场景同批跑）。
5. 插件的自检与 demo **不证明模型会正确选工具**，只证明链路与数据面可用。
6. **语义 Monitor 没有增益**是实测负结果（AUROC ≤ 0.51、0 次 LOST）；
   不要在任何材料里写成"语义信号提升了失败预测"。
